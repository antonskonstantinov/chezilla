# chezilla — помощник по системе «Честный знак»

## Что это

AI-агент-советник по российской системе маркировки «Честный знак». Он изучает официальную документацию и практический опыт, преобразует их в векторную базу знаний и использует для генерации отчётов, ответов на вопросы и разъяснений по требованиям маркировки, а также для практических инструкций по возникшим инцидентам.

## Какую проблему решает

Система «Честный знак» регулируется большим объёмом нормативных документов, которые обновляются, дополняются и содержат нюансы, критичные для бизнеса: сроки, категории товаров, форматы отчётов, штрафы за нарушения. Пользователю — предпринимателю, бухгалтеру, специалисту по комплаенсу — трудно быстро найти актуальный ответ и понять, как требование применяется на практике.

chezilla снимает эту нагрузку: принимает вопрос на естественном языке, находит релевантные фрагменты в документации и практическом опыте, генерирует структурированный отчёт со ссылками на источники. На входе также используются практические шаги по устранению инцидентов от специалистов поддержки — они помогают агенту выдавать практические рекомендации.

## Целевая аудитория

- Предприниматели и сотрудники, отвечающие за маркировку товаров.
- Специалисты по комплаенсу и бухгалтерии.
- Разработчики, которым нужно понять требования «Честного знака» для интеграции своих систем.

## Основные сценарии использования

### 1. Вопрос-ответ по требованиям

Пользователь спрашивает: «Какие сроки маркировки моторных масел в 2026 году?» — агент находит актуальные нормы, проверяет дату вступления в силу и отвечает со ссылкой на документ.

### 2. Генерация отчётов

Пользователь запрашивает отчёт по определённой категории товаров, этапу маркировки или типу нарушения — агент собирает информацию из базы и формирует структурированный документ.

### 3. Разъяснение практических нюансов

Пользователь спрашивает, как требование применяется в реальной ситуации (например, при возврате товара, смене собственника, импорте), — агент комбинирует нормативные источники и практический опыт.

### 4. Практические рекомендации по реальным бизнес-кейсам

Пользователь сообщает: «Мне пришла жалоба, что клиент столкнулся с ошибкой в УПД, вот текст ошибки…» — агент даёт ёмкую пошаговую инструкцию со ссылками на нормативную базу.

## Ключевые компоненты

- **Хранилище знаний.** Векторная база данных с эмбеддингами фрагментов официальной документации и практического опыта. На старте — локальная, с возможностью обновления при выходе новых версий документов.
- **Пайплайн обработки документов.** Загрузка, очистка, разбиение на фрагменты, вычисление эмбеддингов, индексация. Должен распознавать версии документов и помечать актуальность.
- **Пайплайн генерации.** Поиск релевантных фрагментов по запросу, сборка контекста, генерация ответа или отчёта с указанием источников.
- **Интерфейс взаимодействия.** Веб-интерфейс и бот в российском мессенджере MAX.

## Технические предпочтения

- **Векторная БД:** Chroma для быстрого прототипа; Qdrant — если понадобится фильтрация по метаданным и продакшн-надёжность.
- **Модель эмбеддингов:** `intfloat/multilingual-e5-large` или `BGE-m3` — обе хорошо работают с русским языком и допускают локальное развёртывание.
- **Фреймворк оркестрации:** LangChain или LlamaIndex — готовые компоненты VectorStore, Retriever, Generation.
- **Язык разработки:** Python.
